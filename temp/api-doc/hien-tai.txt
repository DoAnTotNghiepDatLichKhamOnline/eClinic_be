[H1] 1. Giới thiệu và phạm vi
Tài liệu mô tả route, request, response và mã lỗi của hai nhóm chức năng trong eClinic backend mà frontend cần để làm phần tài khoản và phần đặt lịch khám của bệnh nhân:
Tài khoản (mục 5-10): xác thực và quản lý tài khoản cho mọi vai trò (bệnh nhân, bác sĩ, quản trị viên), do identity-service cung cấp.
Đặt lịch khám phía bệnh nhân: xem chuyên khoa, bác sĩ và khung giờ; đặt lịch (khách không cần đăng nhập, hoặc bệnh nhân đã đăng nhập); xem, hủy, đổi lịch hẹn; phiếu khám và mã QR; hồ sơ bệnh nhân và người thân đã lưu; lịch sử khám; đánh giá; thông báo. Do catalog-service, booking-service và notification-service cung cấp.
Không có trong tài liệu này: các route đặt lịch của bác sĩ (danh sách lịch hẹn, xác nhận / từ chối, ca làm việc) và của quản trị viên (quản lý lịch hẹn, lịch làm việc, hồ sơ bệnh nhân, danh mục); API của medical-service, chatbot-service, report-service.
Frontend gọi mọi API qua api-gateway (cổng 8080); gateway chuyển tiếp theo tiền tố đường dẫn và giữ nguyên đường dẫn. Bảng tiền tố, cổng và Swagger UI của từng service ở mục 3.8. Quy ước riêng của phần đặt lịch ở mục 3.8-3.11.

[H1] 3. Quy ước chung
[H2] 3.1 Khung phản hồi
Mọi API (trừ lỗi do gateway tự trả, xem 3.4) trả JSON theo một khung. Các trường của khung (maLoi, thongDiep, duLieu, chiTiet) không xuất hiện khi không có giá trị. Bên trong duLieu thì ngược lại: trường không có giá trị vẫn có mặt với giá trị null (vd "anhDaiDien": null), mảng không có phần tử là []. JSON mẫu trong tài liệu có thể lược bớt vài trường đang null cho gọn.
THÀNH CÔNG
{
  "thanhCong": true,
  "thongDiep": "Đăng nhập thành công",
  "duLieu": { ... }
}

LỖI
{
  "thanhCong": false,
  "maLoi": "DU_LIEU_KHONG_HOP_LE",
  "thongDiep": "Dữ liệu không hợp lệ",
  "chiTiet": [
    { "truong": "email", "thongDiep": "Email không đúng định dạng" }
  ]
}

| Trường | Kiểu | Mô tả |
| thanhCong | boolean | true khi thành công, false khi lỗi. |
| maLoi | string | Mã lỗi để frontend xử lý (chỉ có khi lỗi). HTTP status quy định theo mã (Phụ lục A). |
| thongDiep | string | Thông điệp tiếng Việt, hiển thị được cho người dùng. |
| duLieu | object | array | number | Dữ liệu trả về (chỉ có khi thành công và có dữ liệu). |
| chiTiet | array | Chỉ có ở lỗi 400: mỗi phần tử { truong, thongDiep } cho một trường sai. |


[H2] 3.2 Xác thực và phiên đăng nhập
Access token: JWT ký HS256, sống 30 phút (thoiHanAccessToken = 1800 giây). Gửi kèm mọi route cần đăng nhập: Authorization: Bearer <accessToken>. Claim: sub (id tài khoản), email, vaiTro, phien (mã phiên).
Refresh token: chuỗi ngẫu nhiên 43 ký tự, sống 7 ngày, dùng một lần (mỗi lần làm mới cấp token mới). Nằm trong cookie eclinic_rt, không có trong JSON.
Cookie eclinic_rt: HttpOnly; Secure; SameSite=Strict; Path=/api/auth; Max-Age=604800. Trình duyệt chỉ gửi kèm các route /api/auth/*. http://localhost được coi là an toàn nên cookie Secure vẫn hoạt động; chỉ đặt COOKIE_SECURE=false khi mở frontend qua IP LAN bằng http.
Frontend: giữ access token trong bộ nhớ (không lưu localStorage), gọi API với credentials: "include" để cookie đi kèm (gateway đã bật Access-Control-Allow-Credentials cho các origin được phép).
Hết hạn: access token hết hạn → 401 CHUA_DANG_NHAP → gọi POST /api/auth/refresh-token. Nếu refresh trả 401 PHIEN_DANG_NHAP_KHONG_HOP_LE thì chuyển về trang đăng nhập.
Vai trò: BENH_NHAN, BAC_SI, QUAN_TRI_VIEN (lấy từ claim vaiTro).
Route đặt lịch: một số route công khai, không cần token; các route có /cua-toi chỉ dành cho vai trò BENH_NHAN. Xem 3.9.
[H2] 3.3 Phân trang
Route danh sách nhận trang (đánh số từ 0) và kichThuoc; duLieu có dạng:
{
  "noiDung": [ ... ],
  "trang": 0,
  "kichThuoc": 20,
  "tongSoPhanTu": 23,
  "tongSoTrang": 2
}

[H2] 3.4 Lỗi chung
Các lỗi sau có thể xảy ra ở mọi route và không lặp lại trong từng mục.
| HTTP | maLoi | Khi nào |
| 400 | DU_LIEU_KHONG_HOP_LE | Body sai quy tắc (kèm chiTiet), JSON sai định dạng, sai kiểu tham số, thiếu tham số, sai Content-Type. |
| 401 | CHUA_DANG_NHAP | Thiếu token, token sai hoặc hết hạn, hoặc tài khoản đã bị xoá. (Route cần đăng nhập) |
| 403 | KHONG_CO_QUYEN | Vai trò không đủ quyền (vd. không phải quản trị viên gọi route quản trị). |
| 403 | TAI_KHOAN_BI_VO_HIEU_HOA | Tài khoản bị vô hiệu hoá sau khi token được cấp. (Route cần đăng nhập) |
| 403 | TAI_KHOAN_CHUA_XAC_THUC | Tài khoản còn CHO_XAC_NHAN. (Route cần đăng nhập) |
| 404 | KHONG_TIM_THAY | Không có dữ liệu / đường dẫn. |
| 405 | PHUONG_THUC_KHONG_HO_TRO | Sai phương thức HTTP. |
| 409 | XUNG_DOT_DU_LIEU | Vi phạm ràng buộc duy nhất trong CSDL (thường do hai request chạy đồng thời). |
| 413 | TEP_QUA_LON | Tệp tải lên vượt giới hạn (2 MB). |
| 500 | LOI_HE_THONG | Lỗi không mong đợi. |


Lỗi do api-gateway tự trả (body chỉ có thanhCong, maLoi, thongDiep):
| HTTP | maLoi | Khi nào |
| 503 | DICH_VU_KHONG_KHA_DUNG | Service đích chưa chạy hoặc không kết nối được. |
| 504 | DICH_VU_PHAN_HOI_QUA_LAU | Service không trả lời trong 30 giây. |
| 502 | LOI_KET_NOI_DICH_VU | Lỗi kết nối khác tới service. |
| 413 | YEU_CAU_QUA_LON | Body request vượt 5 MB (chưa chuyển tiếp). |
| 404 | KHONG_TIM_THAY | Đường dẫn không thuộc route nào của gateway. |


Lưu ý phân biệt hai lỗi 503: DICH_VU_KHONG_KHA_DUNG là gateway không gọi được service, còn DANG_NHAP_GOOGLE_KHONG_KHA_DUNG và LUU_TRU_ANH_KHONG_KHA_DUNG do chính identity-service trả khi thiếu cấu hình (Phụ lục C).
[H2] 3.5 Quy tắc dữ liệu đầu vào
| Dữ liệu | Quy tắc |
| Email | Tối đa 255 ký tự. Được chuẩn hoá (trim, chữ thường) trước khi lưu và so sánh. Khi đăng ký / đổi email phải đúng định dạng. |
| Mật khẩu mới | Tối thiểu 6 ký tự (quy tắc tạm khi thử nghiệm, sẽ siết lại trước khi triển khai thật) và tối đa 72 byte UTF-8 (giới hạn của BCrypt; chữ có dấu chiếm 2–3 byte mỗi ký tự). |
| Mật khẩu hiện tại / đăng nhập | Chỉ cần không rỗng, tối đa 1000 ký tự. Sai quy tắc cũng chỉ là "mật khẩu không đúng", không phải lỗi 400 về định dạng. |
| Số điện thoại | 10 chữ số, bắt đầu bằng 0 (^0\d{9}$). Duy nhất trong hệ thống. |
| Họ tên | Không rỗng, tối đa 150 ký tự. |
| Token liên kết | Tối đa 100 ký tự (token thật dài 43 ký tự). |
| Ngày giờ | ISO-8601, múi giờ Asia/Ho_Chi_Minh, không kèm offset: 2026-10-03T08:40:00. Ngày: 2001-05-20. |
| Số CCCD | Đúng 12 chữ số. Bắt buộc với người khám từ đủ 18 tuổi (tính theo ngày khám); người dưới 18 tuổi chưa có CCCD thì bỏ trống. Đã lưu vào hồ sơ bệnh nhân thì không đổi được. |
| Ngày sinh | Dạng 2001-05-20, không ở tương lai. |
| Người giám hộ | Bắt buộc khi người khám dưới 18 tuổi tính theo ngày khám (thiếu → 400 THIEU_NGUOI_GIAM_HO). Gồm họ tên, quan hệ (QuanHeGiamHo), số điện thoại, CCCD 12 chữ số khác CCCD người khám; ngày sinh không bắt buộc, có gửi thì phải từ đủ 18 tuổi (sai → 400 NGUOI_GIAM_HO_KHONG_HOP_LE). Người khám từ đủ 18 tuổi thì phần người giám hộ gửi kèm bị bỏ qua. |
| Chuỗi tự do | Lý do khám: bắt buộc, tối đa 500 ký tự. Lý do hủy: không bắt buộc, tối đa 500. Địa chỉ: tối đa 500. Số thẻ bảo hiểm y tế: tối đa 50. Tiền sử bệnh lý: tối đa 5000. Nhận xét đánh giá: tối đa 1000. |
| Trường không bắt buộc | Ở form đặt lịch: không gửi, gửi null hoặc gửi chuỗi rỗng đều được. Ở các route sửa (PUT) của hồ sơ bệnh nhân và người thân đã lưu: gửi trống nghĩa là xoá trắng trường đó. |
| Giờ | Dạng 08:00:00 (kiểu time, giờ của ca làm việc). |


[H2] 3.6 Giới hạn và thời hạn
| Mục | Giá trị |
| Đăng nhập sai mật khẩu | 5 lần → khoá email 15 phút (429 DANG_NHAP_SAI_QUA_NHIEU) |
| Sai mật khẩu hiện tại khi đặt mật khẩu lần đầu (5.11) | Đếm chung với đăng nhập sai: 5 lần → khoá email 15 phút (429 DANG_NHAP_SAI_QUA_NHIEU) |
| Nhập sai mật khẩu hiện tại (đổi mật khẩu, đổi email — dùng chung bộ đếm) | 5 lần → khoá 15 phút (429 SAI_MAT_KHAU_QUA_NHIEU) |
| Chờ giữa hai lần gửi liên kết cho cùng tài khoản | 60 giây (429 GUI_LAI_QUA_NHANH; riêng resend-verification, forgot-password im lặng bỏ qua) |
| Hạn liên kết kích hoạt / đặt lại mật khẩu / đổi email | 24 giờ / 15 phút / 1 giờ; mỗi liên kết dùng một lần |
| Access token / refresh token | 30 phút / 7 ngày |
| Ân hạn dùng lại refresh token đã xoay vòng | 10 giây (quá hạn ân hạn bị coi là token bị lộ) |
| Đổi ảnh đại diện | 10 lần / giờ / tài khoản; tối đa 2 MB mỗi tệp |
| Kích thước body tại gateway | Tối đa 5 MB |
| Đặt lịch trước giờ khám | Ít nhất 30 phút trước giờ bắt đầu lượt khám và trong 30 ngày tới (tính cả hôm nay); ngoài khoảng này khung giờ không hiện, đặt thẳng → 409 KHUNG_GIO_KHONG_KHA_DUNG |
| Số lịch sắp tới còn hiệu lực | Tối đa 3 cho 1 hồ sơ bệnh nhân, 5 cho 1 số điện thoại liên hệ (409 VUOT_GIOI_HAN_DAT_LICH) |
| Số lần gọi đặt lịch, đổi lịch, hủy bằng link phiếu khám từ 1 địa chỉ IP (đếm chung) | 20 lần / 10 phút (429 GUI_LAI_QUA_NHANH) |
| Hủy / đổi lịch | Tới 2 giờ trước giờ khám dự kiến (409 QUA_HAN_HUY_DOI_LICH) |
| Số lần đổi lịch của 1 lần đặt | 2 lần (409 VUOT_SO_LAN_DOI_LICH) |
| Xem khung giờ nhiều ngày của 1 bác sĩ | Tối đa 7 ngày liền mỗi lần gọi |
| Lịch hẹn của tôi theo khoảng ngày (màn hình lịch) | Tối đa 42 ngày mỗi lần gọi |
| Người thân đã lưu | Tối đa 10 người mỗi tài khoản (giữ 10 người đặt gần nhất) |
| Sửa đánh giá đã gửi | Trong 7 ngày kể từ lúc gửi (409 HET_HAN_SUA_DANH_GIA) |
| Ảnh mã QR phiếu khám | Cạnh 100-1000 pixel, mặc định 300 |
| Kích thước trang của các route danh sách | kichThuoc từ 1 đến 100, mặc định 20 |
| Hỏi số thông báo chưa đọc | Không có đẩy realtime: frontend gọi lại khoảng 30 giây một lần, tạm dừng khi tab bị ẩn |

[H2] 3.9 Khách và bệnh nhân đã đăng nhập
Đặt lịch khám không bắt buộc đăng nhập. Các route sau là công khai (không cần access token):
GET /api/catalog/chuyen-khoa/**, GET /api/catalog/bac-si/**: xem chuyên khoa và bác sĩ.
GET /api/booking/khung-gio/**: xem khung giờ còn chỗ.
POST /api/booking/lich-hen: đặt lịch.
GET /api/booking/phieu-kham/** và POST /api/booking/phieu-kham/**: xem phiếu khám, mã QR, hủy và đổi lịch bằng link phiếu khám kèm số điện thoại liên hệ.
Mọi route còn lại của booking-service trong tài liệu này (đường dẫn có /cua-toi) cần access token của vai trò BENH_NHAN; bác sĩ và quản trị viên gọi sẽ nhận 403 KHONG_CO_QUYEN. Các route thông báo (/api/notification/**) dùng cho mọi vai trò đã đăng nhập.
ĐẶT LỊCH KHI CÓ VÀ KHÔNG CÓ TOKEN
| Request | Kết quả |
| Không có header Authorization | Đặt như khách. luuVaoTaiKhoan = false; lịch chỉ xem lại được bằng link phiếu khám. Hủy / đổi bằng maPhieuKham kèm số điện thoại liên hệ. |
| Token của BENH_NHAN | Lịch lưu vào tài khoản (luuVaoTaiKhoan = true), có trong "lịch hẹn của tôi". datChoBanThan và luuNguoiThan của request chỉ có nghĩa ở trường hợp này. |
| Token của BAC_SI / QUAN_TRI_VIEN | 403 KHONG_CO_QUYEN: các vai trò này không đặt lịch khám; đăng xuất để đặt như khách. |
| Token hết hạn hoặc sai | 401 CHUA_DANG_NHAP, kể cả ở route công khai: service kiểm tra mọi token được gửi lên trước khi xét route có công khai hay không. Làm mới token trước, hoặc không gửi header Authorization khi gọi route công khai. |

[H2] 3.11 Vòng đời lịch hẹn, hủy và đổi lịch
| trangThai | Khi nào | Bệnh nhân còn làm được |
| CHO_XAC_NHAN | Vừa đặt hoặc vừa đổi lịch; chờ bác sĩ xác nhận. | Hủy, đổi lịch (trước hạn). |
| DA_XAC_NHAN | Bác sĩ đã xác nhận. | Hủy, đổi lịch (trước hạn). |
| BI_TU_CHOI | Bác sĩ từ chối; lý do ở lyDoHuy. | Không; đặt lịch mới. |
| DA_HOAN_THANH | Bác sĩ đã ghi kết quả khám. | Xem kết quả, gửi / sửa đánh giá. |
| DA_HUY | Lịch đã hủy; lý do (nếu có) ở lyDoHuy. | Không. |
| DA_HUY_DO_DOI_LICH | Lịch cũ sau khi đổi lịch; lịch mới là 1 lịch khác với phiếu khám mới. | Không. |


Chọn khung giờ (đặt lịch và đổi lịch): gửi đúng một trong hai: idLichLamViec + gioBatDauKhung (bác sĩ cụ thể; lấy từ CaKhamResponse) hoặc idChuyenKhoa + gioBatDauKhung (bác sĩ bất kỳ; lấy từ KhungGioGopResponse, hệ thống xếp bác sĩ còn nhiều chỗ nhất). Gửi cả hai hoặc không gửi → 400.
Hạn hủy / đổi: tới hanHuyDoi = giờ khám dự kiến trừ 2 giờ. Quá hạn → 409 QUA_HAN_HUY_DOI_LICH. Dùng duocHuyDoi để ẩn / hiện nút, không tự tính lại ở frontend.
Đổi lịch = hủy lịch cũ + tạo lịch mới: lịch cũ thành DA_HUY_DO_DOI_LICH, response là DatLichResponse của lịch mới (CHO_XAC_NHAN) với maPhieuKham mới. Sau khi đổi, chuyển sang phiếu khám mới; link cũ vẫn mở được và hiện trạng thái đã đổi.
Số lần đổi: tối đa 2 lần cho 1 lần đặt (đếm qua cả chuỗi lịch cũ). Lần thứ 3 → 409 VUOT_SO_LAN_DOI_LICH.
canDoiLich = true: phòng khám đã hủy ca khám, lịch hẹn còn hiệu lực và chờ bệnh nhân đổi sang khung giờ khác (hoặc hủy). Khi đó hủy / đổi được tới giờ khám cũ và lần đổi này không tính vào số lần đổi. Bệnh nhân có tài khoản nhận thông báo LICH_HEN_CAN_DOI.
Lịch đã qua giờ: lịch CHO_XAC_NHAN / DA_XAC_NHAN mà khung giờ đã kết thúc vẫn giữ nguyên trangThai nhưng thuộc bộ lọc LICH_SU, không còn là SAP_TOI.
Ai hủy / đổi được: trên các route /cua-toi, tài khoản là người đặt hoặc là người khám (laBanThan). Trên các route /phieu-kham, bất kỳ ai gửi đúng số điện thoại liên hệ đã nhập lúc đặt (sai → 403 SO_DIEN_THOAI_KHONG_KHOP).

[H1] 7. Ảnh đại diện

[H1] Phụ lục B. Luồng gọi mẫu
[H2] B.1 Đăng ký, kích hoạt, đăng nhập
POST /api/auth/register → 201, tài khoản CHO_XAC_NHAN, email chứa liên kết kích hoạt.
Người dùng mở liên kết <FRONTEND_URL>/verify-email?token=...; frontend gửi POST /api/auth/verify-email với token đó → 200.
POST /api/auth/login → 200, nhận accessToken trong body và cookie eclinic_rt.
Nếu chưa nhận được email: POST /api/auth/resend-verification (cách nhau tối thiểu 60 giây).

[H2] B.2 Duy trì phiên
Gọi API kèm Authorization: Bearer <accessToken>.
Nhận 401 CHUA_DANG_NHAP (access token hết hạn sau 30 phút) → POST /api/auth/refresh-token (cookie tự gửi) → lưu accessToken mới.
Refresh trả 401 PHIEN_DANG_NHAP_KHONG_HOP_LE → chuyển về trang đăng nhập.
Đăng xuất: POST /api/auth/logout, rồi bỏ access token khỏi bộ nhớ.

[H2] B.3 Quên mật khẩu
POST /api/auth/forgot-password với email → luôn 200.
Người dùng mở liên kết <FRONTEND_URL>/reset-password?token=... (hiệu lực 15 phút).
POST /api/auth/reset-password với token và matKhauMoi → 200, mọi thiết bị bị đăng xuất; đăng nhập lại bằng mật khẩu mới.

[H2] B.4 Đổi email
Đang đăng nhập: POST /api/users/me/change-email với emailMoi và matKhauHienTai → 200.
Người dùng mở liên kết gửi tới email mới: <FRONTEND_URL>/confirm-email-change?token=....
Frontend gửi POST /api/auth/confirm-email-change → 200, mọi thiết bị bị đăng xuất; đăng nhập lại bằng email mới.
Muốn bỏ yêu cầu: DELETE /api/users/me/change-email.

[H2] B.5 Quản trị viên vô hiệu hoá tài khoản
GET /api/users?tuKhoa=...&trangThai=DA_KICH_HOAT để tìm tài khoản; GET /api/users/{id} để xem chi tiết.
PUT /api/users/{id}/status với { "trangThai": "VO_HIEU_HOA", "lyDo": "..." } → mọi thiết bị của tài khoản bị đăng xuất, chủ tài khoản nhận email.
Muốn mở lại: PUT /api/users/{id}/status với { "trangThai": "DA_KICH_HOAT" }.

[H2] B.6 Bác sĩ đăng nhập lần đầu
Quản trị viên tạo tài khoản bác sĩ; bác sĩ nhận email báo email đăng nhập, mật khẩu là mật khẩu mặc định của phòng khám.
POST /api/auth/login bằng mật khẩu mặc định → 403 PHAI_DOI_MAT_KHAU, không có phiên.
Frontend hiện form đặt mật khẩu mới, gửi POST /api/auth/first-password với email, matKhauHienTai, matKhauMoi → 200.
POST /api/auth/login bằng mật khẩu mới → 200, nhận accessToken trong body và cookie eclinic_rt.

[H1] Phụ lục C. Cấu hình ảnh hưởng tới API và tài khoản mẫu
Một số API chỉ hoạt động đầy đủ khi identity-service nhận được biến môi trường tương ứng. Khi chạy bằng IntelliJ, service không đọc file .env: phải đặt biến trong Run Configuration của identity-service. Khi chạy bằng Docker Compose thì .env được nạp.
| Biến môi trường | Ảnh hưởng | Triệu chứng khi thiếu |
| GOOGLE_CLIENT_ID | POST /api/auth/google | 503 DANG_NHAP_GOOGLE_KHONG_KHA_DUNG |
| MAIL_MODE (mặc định console) | Mọi email: kích hoạt, đặt lại mật khẩu, đổi email, thông báo | Mặc định không gửi email thật; liên kết chỉ ghi ra log identity-service ([DEV - không gửi email]) |
| MAIL_USERNAME, MAIL_APP_PASSWORD | Bắt buộc khi MAIL_MODE=smtp (App Password Gmail 16 ký tự, viết liền) | identity-service không khởi động |
| CLOUDINARY_CLOUD_NAME, CLOUDINARY_API_KEY, CLOUDINARY_API_SECRET | POST /api/users/me/avatar | 503 LUU_TRU_ANH_KHONG_KHA_DUNG |
| FRONTEND_URL | Gốc của các liên kết trong email (mặc định http://localhost:5173) | Liên kết trỏ sai địa chỉ frontend |
| COOKIE_SECURE | Cờ Secure của cookie refresh token (mặc định true) | Cookie không được gửi khi mở frontend qua IP LAN bằng http |

| DOCTOR_DEFAULT_PASSWORD | Mật khẩu mặc định của tài khoản bác sĩ do quản trị viên tạo; dùng ở POST /api/auth/first-password | Không đặt thì dùng Doctor@123 |
| CORS_ALLOWED_ORIGINS | Đặt cho api-gateway: các địa chỉ frontend được gọi API (mặc định http://localhost:5173, http://localhost:3000) | Frontend chạy ở địa chỉ khác bị trình duyệt chặn vì CORS |
