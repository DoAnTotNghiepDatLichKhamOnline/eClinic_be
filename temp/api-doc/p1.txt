[H1] 1. Giới thiệu và phạm vi
Tài liệu mô tả route, request, response và mã lỗi của hai nhóm chức năng đã hoàn thiện trong eClinic backend: xác thực và quản lý tài khoản. Cả hai do identity-service (cổng 8081) cung cấp. Frontend gọi qua api-gateway (cổng 8080); gateway chuyển tiếp /api/auth/**, /api/users/** và /api/identity/** tới identity-service và giữ nguyên đường dẫn.
Chưa có trong bản này: API của các service còn lại (catalog-service, booking-service, medical-service, notification-service, chatbot-service, report-service).
Mỗi service có Swagger UI riêng, ví dụ http://localhost:8081/swagger-ui.html cho identity-service.

[H1] 3. Quy ước chung
[H2] 3.1 Khung phản hồi
Mọi API (trừ lỗi do gateway tự trả, xem 3.4) trả JSON theo một khung. Trường có giá trị null không xuất hiện trong JSON.
THÀNH CÔNG
{
  "thanhCong": true,
  "thongDiep": "Đăng nhập thành công",
  "duLieu": { ... }
}

LỖI
{
  "thanhCong": false,
  "maLoi": "DU_LIEU_KHONG_HOP_LE",
  "thongDiep": "Dữ liệu không hợp lệ",
  "chiTiet": [
    { "truong": "email", "thongDiep": "Email không đúng định dạng" }
  ]
}

| Trường | Kiểu | Mô tả |
| thanhCong | boolean | true khi thành công, false khi lỗi. |
| maLoi | string | Mã lỗi để frontend xử lý (chỉ có khi lỗi). HTTP status quy định theo mã (Phụ lục A). |
| thongDiep | string | Thông điệp tiếng Việt, hiển thị được cho người dùng. |
| duLieu | object | array | number | Dữ liệu trả về (chỉ có khi thành công và có dữ liệu). |
| chiTiet | array | Chỉ có ở lỗi 400: mỗi phần tử { truong, thongDiep } cho một trường sai. |


[H2] 3.2 Xác thực và phiên đăng nhập
Access token: JWT ký HS256, sống 30 phút (thoiHanAccessToken = 1800 giây). Gửi kèm mọi route cần đăng nhập: Authorization: Bearer <accessToken>. Claim: sub (id tài khoản), email, vaiTro, phien (mã phiên).
Refresh token: chuỗi ngẫu nhiên 43 ký tự, sống 7 ngày, dùng một lần (mỗi lần làm mới cấp token mới). Nằm trong cookie eclinic_rt, không có trong JSON.
Cookie eclinic_rt: HttpOnly; Secure; SameSite=Strict; Path=/api/auth; Max-Age=604800. Trình duyệt chỉ gửi kèm các route /api/auth/*. http://localhost được coi là an toàn nên cookie Secure vẫn hoạt động; chỉ đặt COOKIE_SECURE=false khi mở frontend qua IP LAN bằng http.
Frontend: giữ access token trong bộ nhớ (không lưu localStorage), gọi API với credentials: "include" để cookie đi kèm (gateway đã bật Access-Control-Allow-Credentials cho các origin được phép).
Hết hạn: access token hết hạn → 401 CHUA_DANG_NHAP → gọi POST /api/auth/refresh-token. Nếu refresh trả 401 PHIEN_DANG_NHAP_KHONG_HOP_LE thì chuyển về trang đăng nhập.
Vai trò: BENH_NHAN, BAC_SI, QUAN_TRI_VIEN (lấy từ claim vaiTro).
[H2] 3.3 Phân trang
Route danh sách nhận trang (đánh số từ 0) và kichThuoc; duLieu có dạng:
{
  "noiDung": [ ... ],
  "trang": 0,
  "kichThuoc": 20,
  "tongSoPhanTu": 23,
  "tongSoTrang": 2
}

[H2] 3.4 Lỗi chung
Các lỗi sau có thể xảy ra ở mọi route và không lặp lại trong từng mục.
| HTTP | maLoi | Khi nào |
| 400 | DU_LIEU_KHONG_HOP_LE | Body sai quy tắc (kèm chiTiet), JSON sai định dạng, sai kiểu tham số, thiếu tham số, sai Content-Type. |
| 401 | CHUA_DANG_NHAP | Thiếu token, token sai hoặc hết hạn, hoặc tài khoản đã bị xoá. (Route cần đăng nhập) |
| 403 | KHONG_CO_QUYEN | Vai trò không đủ quyền (vd. không phải quản trị viên gọi route quản trị). |
| 403 | TAI_KHOAN_BI_VO_HIEU_HOA | Tài khoản bị vô hiệu hoá sau khi token được cấp. (Route cần đăng nhập) |
| 403 | TAI_KHOAN_CHUA_XAC_THUC | Tài khoản còn CHO_XAC_NHAN. (Route cần đăng nhập) |
| 404 | KHONG_TIM_THAY | Không có dữ liệu / đường dẫn. |
| 405 | PHUONG_THUC_KHONG_HO_TRO | Sai phương thức HTTP. |
| 409 | XUNG_DOT_DU_LIEU | Vi phạm ràng buộc duy nhất trong CSDL (thường do hai request chạy đồng thời). |
| 413 | TEP_QUA_LON | Tệp tải lên vượt giới hạn (2 MB). |
| 500 | LOI_HE_THONG | Lỗi không mong đợi. |


Lỗi do api-gateway tự trả (body chỉ có thanhCong, maLoi, thongDiep):
| HTTP | maLoi | Khi nào |
| 503 | DICH_VU_KHONG_KHA_DUNG | identity-service chưa chạy hoặc không kết nối được. |
| 504 | DICH_VU_PHAN_HOI_QUA_LAU | Service không trả lời trong 30 giây. |
| 502 | LOI_KET_NOI_DICH_VU | Lỗi kết nối khác tới service. |
| 413 | YEU_CAU_QUA_LON | Body request vượt 5 MB (chưa chuyển tiếp). |
| 404 | KHONG_TIM_THAY | Đường dẫn không thuộc route nào của gateway. |


Lưu ý phân biệt hai lỗi 503: DICH_VU_KHONG_KHA_DUNG là gateway không gọi được service, còn DANG_NHAP_GOOGLE_KHONG_KHA_DUNG và LUU_TRU_ANH_KHONG_KHA_DUNG do chính identity-service trả khi thiếu cấu hình (Phụ lục C).
[H2] 3.5 Quy tắc dữ liệu đầu vào
| Dữ liệu | Quy tắc |
| Email | Tối đa 255 ký tự. Được chuẩn hoá (trim, chữ thường) trước khi lưu và so sánh. Khi đăng ký / đổi email phải đúng định dạng. |
| Mật khẩu mới | Tối thiểu 6 ký tự (quy tắc tạm khi thử nghiệm, sẽ siết lại trước khi triển khai thật) và tối đa 72 byte UTF-8 (giới hạn của BCrypt; chữ có dấu chiếm 2–3 byte mỗi ký tự). |
| Mật khẩu hiện tại / đăng nhập | Chỉ cần không rỗng, tối đa 1000 ký tự. Sai quy tắc cũng chỉ là "mật khẩu không đúng", không phải lỗi 400 về định dạng. |
| Số điện thoại | 10 chữ số, bắt đầu bằng 0 (^0\d{9}$). Duy nhất trong hệ thống. |
| Họ tên | Không rỗng, tối đa 150 ký tự. |
| Token liên kết | Tối đa 100 ký tự (token thật dài 43 ký tự). |
| Ngày giờ | ISO-8601, múi giờ Asia/Ho_Chi_Minh, không kèm offset: 2026-10-03T08:40:00. Ngày: 2001-05-20. |


[H2] 3.6 Giới hạn và thời hạn
| Mục | Giá trị |
| Đăng nhập sai mật khẩu | 5 lần → khoá email 15 phút (429 DANG_NHAP_SAI_QUA_NHIEU) |
| Sai mật khẩu hiện tại khi đặt mật khẩu lần đầu (5.11) | Đếm chung với đăng nhập sai: 5 lần → khoá email 15 phút (429 DANG_NHAP_SAI_QUA_NHIEU) |
| Nhập sai mật khẩu hiện tại (đổi mật khẩu, đổi email — dùng chung bộ đếm) | 5 lần → khoá 15 phút (429 SAI_MAT_KHAU_QUA_NHIEU) |
| Chờ giữa hai lần gửi liên kết cho cùng tài khoản | 60 giây (429 GUI_LAI_QUA_NHANH; riêng resend-verification, forgot-password im lặng bỏ qua) |
| Hạn liên kết kích hoạt / đặt lại mật khẩu / đổi email | 24 giờ / 15 phút / 1 giờ; mỗi liên kết dùng một lần |
| Access token / refresh token | 30 phút / 7 ngày |
| Ân hạn dùng lại refresh token đã xoay vòng | 10 giây (quá hạn ân hạn bị coi là token bị lộ) |
| Đổi ảnh đại diện | 10 lần / giờ / tài khoản; tối đa 2 MB mỗi tệp |
| Kích thước body tại gateway | Tối đa 5 MB |

[H1] 5. Xác thực (AUTH)
Nhóm route /api/auth/** đều công khai: không cần access token. Đăng nhập và làm mới phiên trả access token trong body, còn refresh token đi trong cookie HttpOnly eclinic_rt (xem mục 3.2).
[H3] 5.1  Đăng ký tài khoản bệnh nhân
| POST | /api/auth/register |


Quyền truy cập: Công khai (không cần access token)
Bệnh nhân tự đăng ký. Hệ thống tạo tài khoản trạng thái CHO_XAC_NHAN và gửi email chứa liên kết kích hoạt. Tài khoản chưa đăng nhập được cho tới khi kích hoạt (xem 5.2).
REQUEST BODY (JSON)
| Trường | Kiểu | Bắt buộc | Ràng buộc / mô tả |
| hoTen | string | Có | Không rỗng, tối đa 150 ký tự (được trim). |
| email | string | Có | Đúng định dạng email, tối đa 255 ký tự. Được chuẩn hoá: trim và chữ thường. |
| matKhau | string | Có | Tối thiểu 6 ký tự, tối đa 72 byte UTF-8. |
| soDienThoai | string | Có | 10 chữ số, bắt đầu bằng 0 (^0\d{9}$). |
| cccd | string | Không | Số CCCD gồm đúng 12 chữ số; bỏ trống hoặc không gửi nếu không khai. Xem lưu ý. |


{
  "hoTen": "Nguyễn Văn An",
  "email": "an.nguyen@example.com",
  "matKhau": "MatKhau@123",
  "soDienThoai": "0901234567",
  "cccd": "079201000001"
}

[H1] 7. Ảnh đại diện
Ảnh lưu ở Cloudinary, mỗi tài khoản một ảnh. Mọi vai trò đều gọi được, luôn thao tác trên tài khoản của chính người gọi.

[H1] 9. Thiết bị đang đăng nhập

[H1] 10. Quản trị tài khoản

[H1] Phụ lục B. Luồng gọi mẫu
[H2] B.1 Đăng ký, kích hoạt, đăng nhập
POST /api/auth/register → 201, tài khoản CHO_XAC_NHAN, email chứa liên kết kích hoạt.
Người dùng mở liên kết <FRONTEND_URL>/verify-email?token=...; frontend gửi POST /api/auth/verify-email với token đó → 200.
POST /api/auth/login → 200, nhận accessToken trong body và cookie eclinic_rt.
Nếu chưa nhận được email: POST /api/auth/resend-verification (cách nhau tối thiểu 60 giây).

[H2] B.2 Duy trì phiên
Gọi API kèm Authorization: Bearer <accessToken>.
Nhận 401 CHUA_DANG_NHAP (access token hết hạn sau 30 phút) → POST /api/auth/refresh-token (cookie tự gửi) → lưu accessToken mới.
Refresh trả 401 PHIEN_DANG_NHAP_KHONG_HOP_LE → chuyển về trang đăng nhập.
Đăng xuất: POST /api/auth/logout, rồi bỏ access token khỏi bộ nhớ.

[H2] B.3 Quên mật khẩu
POST /api/auth/forgot-password với email → luôn 200.
Người dùng mở liên kết <FRONTEND_URL>/reset-password?token=... (hiệu lực 15 phút).
POST /api/auth/reset-password với token và matKhauMoi → 200, mọi thiết bị bị đăng xuất; đăng nhập lại bằng mật khẩu mới.

[H2] B.4 Đổi email
Đang đăng nhập: POST /api/users/me/change-email với emailMoi và matKhauHienTai → 200.
Người dùng mở liên kết gửi tới email mới: <FRONTEND_URL>/confirm-email-change?token=....
Frontend gửi POST /api/auth/confirm-email-change → 200, mọi thiết bị bị đăng xuất; đăng nhập lại bằng email mới.
Muốn bỏ yêu cầu: DELETE /api/users/me/change-email.

[H2] B.5 Quản trị viên vô hiệu hoá tài khoản
GET /api/users?tuKhoa=...&trangThai=DA_KICH_HOAT để tìm tài khoản; GET /api/users/{id} để xem chi tiết.
PUT /api/users/{id}/status với { "trangThai": "VO_HIEU_HOA", "lyDo": "..." } → mọi thiết bị của tài khoản bị đăng xuất, chủ tài khoản nhận email.
Muốn mở lại: PUT /api/users/{id}/status với { "trangThai": "DA_KICH_HOAT" }.

[H2] B.6 Bác sĩ đăng nhập lần đầu
Quản trị viên tạo tài khoản bác sĩ; bác sĩ nhận email báo email đăng nhập, mật khẩu là mật khẩu mặc định của phòng khám.
POST /api/auth/login bằng mật khẩu mặc định → 403 PHAI_DOI_MAT_KHAU, không có phiên.
Frontend hiện form đặt mật khẩu mới, gửi POST /api/auth/first-password với email, matKhauHienTai, matKhauMoi → 200.
POST /api/auth/login bằng mật khẩu mới → 200, nhận accessToken trong body và cookie eclinic_rt.

[H1] Phụ lục C. Cấu hình ảnh hưởng tới API và tài khoản mẫu
Một số API chỉ hoạt động đầy đủ khi identity-service nhận được biến môi trường tương ứng. Khi chạy bằng IntelliJ, service không đọc file .env: phải đặt biến trong Run Configuration của identity-service. Khi chạy bằng Docker Compose thì .env được nạp.
| Biến môi trường | Ảnh hưởng | Triệu chứng khi thiếu |
| GOOGLE_CLIENT_ID | POST /api/auth/google | 503 DANG_NHAP_GOOGLE_KHONG_KHA_DUNG |
| MAIL_MODE (mặc định console) | Mọi email: kích hoạt, đặt lại mật khẩu, đổi email, thông báo | Mặc định không gửi email thật; liên kết chỉ ghi ra log identity-service ([DEV - không gửi email]) |

| CLOUDINARY_CLOUD_NAME, CLOUDINARY_API_KEY, CLOUDINARY_API_SECRET | POST /api/users/me/avatar | 503 LUU_TRU_ANH_KHONG_KHA_DUNG |
